# H3 CPU 联合分窗采样

全局音视频 latent、噪声、融合缓冲及采样器历史留在 CPU。每个 sigma 顺序执行短窗 GPU 预测，融合全部窗口的 x0 后才更新一次全局状态。插件复用原生模型、LoRA、attention 和 VAE；本机另外保留了 FastH3 PDD 输出头兼容补丁。

2026-10-23 最新状态：已按用户要求回退无 source-ControlNet。节点注册、编码分支、运行时控制 latent 切换均已移除；主视频恢复原生 REF2VA 参考与 `<Video 1>` 标签。当前交付入口是包外 `H3_v4_无ControlNet_回退版.json`；完整路径、用户要求、代码地图和检查范围见包外 `H3_最新版本交接文档_2026-10-23.md`。本次未运行生成，画质问题不能视为已解决。

## 总长度与首尾预览 v4 审查版（2026-10-23）

新增 `H3LengthReferenceEncode`，旧节点及旧工作流保留。`height` 下的 `length` 控制整条输出总帧数；24 FPS 下通过原生整数和数学表达式节点计算 `5+17*((24*a+12)//17)`，严格超过输入秒数：5→124、6→158、8→209、13→328。主视频不足时复制末帧；多路主视频仍须原始长度一致。精确总长模式不丢尾段，因此新版不再显示旧的丢尾阈值。为合法采样窗口额外补的帧仍由输出裁帧节点去掉。

`images` 是标准 IMAGE 批次：第一路主视频每窗首帧在左、最后有效目标帧在右，N窗输出N张，接原生 Preview Image。预览按当前分段与外部视频resize生成，不是采样结果。正常编码复用当前窗，首尾拼图复制到独立小张量，不保留整窗RGB；`preview_only` 只读各窗端点。预览图批次自身内存随窗口数增长。

图片使用原生 ImageScale；视频使用 `H3WindowVideoResize` 保存缩放设置，逐窗读取时调用原生 ImageScale。它保持标准 VIDEO 接口；若接整片 GetVideoComponents/SaveVideo，则会物化整条视频。新版取消Clip宽高上限和参考VAE预处理的768短边/面积上限，保留32像素对齐；Qwen视觉编码器自身的token预算预处理不变。

Clip进度按完成窗数更新，并显示计数和百分比。采样进度按窗口数×实际sigma步数更新，3窗10步即30个单位。此比例是完成任务数，不代表剩余时间。输出VAE路径仍为原生完整批次解码，不是流式解码。此次回退只做CPU导入、接口、逻辑测试和工作流静态检查。

## 原生接口 v3 审查版（2026-10-22）

新增 `H3NativeReferenceEncode`：接官方 `VIDEO`，主视频同步逐窗读取，辅助视频每窗从头截取；多主视频按24 FPS计算的帧数必须相同。图片、主视频、辅助视频、视频配套音轨、独立音频、提示词均为动态接口。配套音轨按合并后的视频编号对应，原生 `<Audio n>` 标签仅对实际音轨连续编号。配套 AUDIO 必须已与输入 VIDEO 对齐同一时间段。

新增 `H3NativeWindowSampler`：`RandomNoise → NOISE`，外接 `SAMPLER` 和 `SIGMAS`；全局生成一次噪声。按当前 `sigma >= cfg_split` 取 `high_cfg`，否则取 `low_cfg`。FastH3/PDD 接 Euler；普通 H3 额外支持已适配的固定时间网格采样器，详见错误提示。

配套三窗／完整版使用原生加载和输出节点。`output_frames` 是 INT，接 `ImageFromBatch.length`；原生解码和裁帧仍会保留／复制完整 RGB 批次，并非流式解码。`preview_only` 阻断本节点编码与下游采样，但原生下游独立加载器仍可能由调度加载 VAE。此次仅作界面与静态检查，未执行工作流；下文历史验证不适用于 v3 的新增路径。

## 自动分窗版（2026-10-22）

新工作流 `FastH3_自动分窗_三窗测试.json` / `FastH3_自动分窗_完整流程.json` 已把参考编码、联合采样、VAE解码、裁剪和MP4保存合在一个流程中。把本目录安装到 `custom_nodes` 后重启并刷新浏览器。旧节点继续兼容；下文的4步/LoRA配置仅用于旧模型。

`H3AutoWindowEncode` 逐窗读取视频并调用原生REF2VA，每窗结束释放该窗RGB，CPU保留条件。支持 uniform/manual；窗长最低90且满足5+17k，步进17，无人为最大窗长。手工长度用逗号/空格/换行分隔，不会隐式重复最后一项；保留尾窗需有对应项，最后一项按真实尾段调整。

`minimum_overlap` 是全局最低重叠。实际推进为 `51 * floor((前窗长度 - 最低重叠) / 51)`，实际重叠可能更大。后窗必须能推进。`tail_keep_threshold` 默认40，只计未覆盖的新帧；小于阈值丢弃，等于或大于保留。保留尾窗覆盖重叠+新帧，取至少90的最短合法长度，复制末帧补齐，解码后裁回原长；补帧可能超过16帧。

`per_segment_prompts=true` 时，连接数须等于最终窗数；false只请求数字顺序第一个已连接提示词。相同文本仍分别结合对应源视频编码。原生Autogrow端口每连接一个自动新增一个空端口，目前最多100个独立提示词；共用模式不受该窗口数量限制。

`preview_only=true` 只产生分段报告，经 `H3WindowPlanPreview` 展示；不加载CLIP、VAE、人物图或主模型。关闭后正常生成。`frame_limit=0` 表示读取全片；默认124/22下，328帧是三窗测试。

所有正向和负向编码完成后，通过ComfyUI模型管理接口卸载CLIP及编码VAE。采样器 `unload_model_after_sampling=true` 时卸载主模型及克隆，`H3JointDecode` 随后加载VAE、连续解码并裁剪。卸载释放GPU驻留，不保证删除所有CPU模型对象和缓存。

详见包外 `FastH3_自动分窗_使用说明.md`。自动版仍不是流式RGB输出，内存限制见下文。

## 旧版手工窗口流程

把本目录放入 ComfyUI 的 `custom_nodes`，重启 ComfyUI。导入同包提供的 `H3_CPU_Joint_3Windows.json`。首次为 288×512、4 步、CFG 1、Euler/simple；标准 REF2VA 模型与 4 步 LoRA。示例已使用本机存在的模型和完整着装人物参考，若换机器需重新选择文件。

三路原生 `MiniMaxH3ReferenceToVideo` 必须分别连接对应的源视频切片和视频 VAE。人物图、提示词、模型可以共用，三份 positive 不要合并。

| 窗口 | 源帧区间（右端不含） | 起点 | 长度 |
|---|---|---:|---:|
| 1 | [0,124) | 0 | 124 |
| 2 | [102,226) | 102 | 124 |
| 3 | [204,328) | 204 | 124 |

每窗约 5.167 秒，重叠 22 帧，总计 328 帧 / 13.667 秒。视频按真实时间统一到 H3 的 24 fps；不改变片段播放速度。非 24 fps 源视频的取帧会发生丢帧或重复，模型仍不保证动作逐帧精确重演。

`H3 Joint Window` 依次连接 `previous_windows`，最后一个连接 `H3 CPU Window Sampler`。不接 MotionContext、Guide、旧完成品 latent 或 noise_mask。只接受原生空 AV latent 模板，避免静默忽略已有内容。

解码器接联合采样器的唯一全局 latent，保持原生连续 VAE 解码；示例保存静音视频。音频仍参与 H3 联合去噪并正确融合，可另接原生音频解码或附加原始音轨。

## 限制与资源

- 每窗必须是 `17k+5` 帧；旧158帧上限已移除。自动节点要求至少90帧；旧手工节点仍允许原生较短窗。取消上限不消除长窗动作时序偏差或资源需求。
- 起点须为 51 帧的倍数，同时对齐视频 latent 周期和 40 Hz 音频。124/22 是本版默认；158 帧可用 56 或 5 帧重叠。
- 仅支持单 GPU 原生 H3。新版外接采样器对 FastH3/PDD 仅支持固定网格 Euler；普通 H3 支持 Euler、res_multistep、dpmpp_2m、lms、ipndm、ipndm_v。SIGMAS须由1严格递减至0。常规模型 LoRA 可用；区域mask、ControlNet、CFG++、多GPU和未知自定义采样器不在支持范围。未验证第三方缓存、编译及 PREDICT_NOISE/SAMPLER_SAMPLE 包装插件。
- CPU 强制保存全局状态；显存仍需容纳一窗的权重、参考条件和模型中间特征。原生 ComfyUI 的模型内存估计仍为近似值。
- 不创建全长逐步预览，不保存所有步的历史，不缓存各窗口的 KV。准备后的文本与输入参考张量保存在 CPU，当前前向按原生路径送 GPU。
- 原生 VAE 会分块计算，但解码结果仍是完整 CPU RGB 张量。后续扩到更长视频时，需要另行做流式输出以限制 RAM。
- 运行报告包含帧数、窗口调用次数、耗时及 PyTorch CUDA 峰值分配/保留量。统计区间包含采样器的模型加载与条件准备；原生动态权重加载器的显存未必全部计入 PyTorch 分配器，因此该值不等同整卡占用，也不是全长 latent 大小。

## 扩展方式

先验证三窗的画质、颜色、衣服结构和动作时间，再增加窗口。当前v4修改外接秒数，经公式连接总 `length`；旧自动版修改 `frame_limit` 或设0读取全片。两者均无需手动复制切片/编码节点；逐段提示词模式需要同步增加提示词连接。旧版手工节点仍需各窗独立条件及合法起点。

数值测试确认的是共享状态、融合、音视频坐标与生命周期；不能据此声称消除了长期外观漂移。建议与独立生成及递归续接分别对照。

## 开发测试

自动版使用 ComfyUI Python 执行 `python -m unittest discover -s tests -p "test_*.py"`。49项测试覆盖时间网格、共享状态、尾段策略、CFR/VFR读取、动态输入、整图预览、错误提前终止、补帧裁剪及阶段卸载；不加载真实权重的测试不代表画质验证。

使用 ComfyUI 的 Python 运行 `tests/test_windows.py` 和 `tests/test_runtime.py`。后者默认读取 `D:\ComfyUI_windows_portable\ComfyUI` 的真实 sampler，可用环境变量 `COMFYUI_ROOT` 指定其他路径；测试替换权重与模型预测，不加载真实检查点。

2026-10-21：15 项融合/时间格测试与 3 项原生 sampler 集成测试通过；RTX 5080 16GB 上三窗真实生成完成，288×512、328 帧、4 步，共 12 次窗口预测。采样器耗时 51.62 秒，整个工作流 126.89 秒。监测到的整卡占用峰值约 15.42 GiB；采样器报告的 PyTorch 峰值分配约 684 MiB，二者统计范围不同。低分辨率抽帧仍可见腰带、衣襟细节变化，尚不代表长期服装一致性或逐帧动作已解决。
