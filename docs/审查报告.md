## 一、工作流旧版残留（widget 错位）

方法：拉取 ComfyUI `/object_info` 现网 schema，按「有 widget 的输入」顺序与各节点 `widgets_values` 逐位置比对类型。

### 1. 🔴 `PROYYMaskedSampler` 的 `rolling_front_high` 被顶成布尔（两版都存在）

| 节点 | widgets_values | 期望 |
|---|---|---|
| 基础版 `#20` | `1, 0.79, 1, 0, true, 0.5, resample, **true**, 0.63, true` | pos7 `rolling_front_high` 应为 FLOAT（如 0.9） |
| 二采版 `#20` | 同上（`rolling_enabled=false`） | 同上 |
| 二采版 `#107` | `1, 0.78, 1, 0, false, 1, resample, **true**, 0.63, true` | 同上 |

原因：节点早期版本新增了 `rolling_strength` 参数，旧工作流的布尔值顺位后移一位，`rolling_front_high` 收到 `true`（会被当作 1.0）。
影响：rolling 开启时前段强度 = 1.0；`基础版 #20` 的 `rolling_enabled` 还是 `true`，一采行为与"关闭滚动"版本不同。
建议：手动把该位改回浮点（0.9），`#20` 的 rolling 是否保留按需。

### 2. 🟡 `PROYYImageScale` 的 `target_mp = 0.25`（两版都有）

`#17`：`file, 384, 672, area, center, false, **0.25**, 328, 0`（末尾两个空串是前端上传/预览控件，非参数）。

实测 `resolve_generation_size(384, 672, 0.25)`：

```
mp 0.0   -> (384, 672)
mp 0.25  -> (384, 672)     ← 当前值，恰好等于目标
mp 0.258 -> (416, 704)
mp 0.3   -> (448, 736)
```

即 0.25M 是"像素总量下限"，当前恰好解析回 384×672。**不是错**，但它把尺寸绑定在 0.25MP 上：一旦把宽高改成更小的值，输出会被顶到 ≥0.25MP 的档位（如 416×704），而 `#17` 的宽/高输出正喂给全局 `WIDTH/HEIGHT`，会连带改一采画布、latent 与二采倍率。
建议：若目标是严格 384×672，置 `target_mp = 0`。

### 3. 🟡 `read_frames = 328` 与源视频帧数不符

`#17.read_frames = 328`，而示例源视频 `七月 (93).mp4` 实际 **269 帧**（720×1280 HEVC / 8.99 s）。读取会被钳到 269，不报错，但表意错误。
建议：改成 269 或置 0（全部）。

### 4. 🟡 二采版 `#97 INTConstant = 9` → 总长 226 帧

`#37 = 5 + 17*((24*a+12)//17)`，`a = 9` → **226 帧**（latent T=67）。
与示例成片（124 帧用户结果）无关，但若要与源视频全长对齐需改为 269（→ 271 帧）或对应值。
注意二采会校验 `covered == latent 帧数`，此处与一采必须一致。

### 5. ⚪ 无害的"多值"

- `RandomNoise` 多一个 `fixed`（`control_after_generate`，前端控件）；
- `LoadImage` 多一个 `image`（上传控件）；
- `PROYYImageScale` 多两个空串（上传/预览控件）。
均非参数错位。

### 6. ⚪ 死节点（不影响运行）

- 基础版：二采版专有的 `#134/#139/#140`（SIGMA_1 链）、`#147/#148 BasicScheduler` 无消费者；
- 二采版：同上，`#147/#148` 与 `#139/#141` 的 switch 只在把开关切到 `false` 时才会用到。
- 二采版 `#126 SetNode` 名为 `LATNET_2`（拼写应为 LATENT_2），功能正常，仅命名。

## 二、节点中英文文案问题

### 现状

8 个 PROYY 节点的**显示名全部为英文**（带 `۞▷…◁۞` 装饰），描述中英混排：

| 节点 | 当前显示名 | 描述语言 |
|---|---|---|
| PROYYImageScale | ۞▷Resize Video◁۞ | 中文 |
| PROYYMaskedSampler | ۞▷Window Sampler◁۞ | 英文 |
| PROYYMiniMaxH3ReferenceToVideo | ۞▷Reference to Window◁۞ | 中文 |
| PROYYPreviewAny | ۞▷Preview Any◁۞ | 英文 |
| PROYYRefModFrames | ۞▷Refmod Frames◁۞ | 中文 |
| PROYYRefModInject | ۞▷Refmod Inject◁۞ | 中文 |
| PROYYTiledLatentUpscale | ۞▷Latent Upscale◁۞ | 中文 |
| PROYYStreamVAEDecode | ۞▷Stream VAE Decode◁۞ | 中文 |

### 参数中文名覆盖率严重不均

| 节点 | 参数总数 | 有中文 display_name | 覆盖率 |
|---|---|---|---|
| PROYYImageScale | 9 | 6 | 67% |
| PROYYTiledLatentUpscale | 8 | 2 | 25% |
| PROYYStreamVAEDecode | 8 | 3 | 38% |
| PROYYMaskedSampler | 16 | **0** | **0%** |
| PROYYMiniMaxH3ReferenceToVideo | 28 | **0** | **0%** |
| PROYYPreviewAny | 1 | 0 | 0% |

`Reference to Window` 与 `Window Sampler` 是用户最常调的两个节点，参数却全是英文原名（`auto_segment`、`keep_final`、`rolling_front_low`…），与其它节点的中文界面割裂。

### 具体缺翻译清单（建议补充）

**PROYYMiniMaxH3ReferenceToVideo**（28）
`auto_segment` 自动分段 / `auto_prompt` 自动分配提示词 / `window_frames` 每窗帧数 / `manual_lengths` 手动窗长 / `overlap` 窗重叠 / `keep_final` 末窗保留 / `width` 宽 / `height` 高 / `length` 总帧数 / `text_weight` 文本增益 / `image_weight` 图片增益 / `video_weight` 视频增益 / `video_encode` 视频作初始latent / `unload` 用完卸载模型 / `preview_only` 仅预览计划 / `ref_cache` 参考编码缓存 / `ref_cache_mb` 缓存上限(MB) / `second_pass_windows` 二采复用窗计划 / `source_latent` 二采初始latent，以及 clip/vae/audio_vae（模型输入可保持英文）

**PROYYMaskedSampler**（16）
`noise` 噪声 / `model` 模型 / `windows` 窗 / `sampler` 采样器 / `sigmas` sigma序列 / `high_cfg` 高段CFG / `cfg_split` CFG分段点 / `low_cfg` 低段CFG / `mask` 蒙版 / `fusion_preserve` 融合保留 / `rolling_enabled` 启用滚动 / `rolling_strength` 滚动强度 / `rolling_mode` 滚动模式 / `rolling_front_high` 前段高强度 / `rolling_front_low` 前段低强度 / `unload` 用完卸载

**PROYYImageScale 缺**：`file` 视频文件 / `upscale_method` 缩放算法 / `crop` 裁切方式
**PROYYTiledLatentUpscale 缺**：`model_name` 放大模型 / `scale` 倍率 / `align` 对齐倍数 / `precision` 精度 / `device` 设备
**PROYYStreamVAEDecode 缺**：`latent` / `vae` / `crf` 质量(crf) / `fps` 帧率 / `audio` 音轨

### 一致性问题

1. **命名风格不统一**：`۞▷…◁۞` 装饰全有，但有的名字用动词短语（Resize Video）、有的用名词（Latent Upscale）。
2. **术语混用**：「窗 / window」「分段 / segment」「二采 / second pass」「参考 / reference」在 tooltip 里交替出现。
3. **`Refmod` 缩写无解释**（Refmod Frames / Refmod Inject），新用户无法从名字得知是"参考帧修改注入"。

### 建议最小改动集

1. 显示名统一为「中文（English）」双语，如 `۞▷窗采样◁۞ (Window Sampler)`；
2. 先补 `Reference to Window`、`Window Sampler` 两节点的参数中文名（覆盖 90% 使用场景）；
3. tooltip 术语表统一：窗（window）、分段（segment）、一采/二采（pass 1/2）、参考编码（reference encoding）；
4. 二采模式专有参数（`second_pass_windows`、`source_latent`）在 tooltip 注明"仅二采用"。
